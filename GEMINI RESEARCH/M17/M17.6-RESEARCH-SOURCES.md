# M17.6 — Research Sources: Days 9–12 (Batch 3)

**Zero external sources were opened this batch.**

This is a deliberate, documented outcome, not an omission. The M17 instructions are explicit
("once you have enough evidence to classify a day as KEEP, stop researching that day... the
objective is instructional quality, not research volume") and explicit that research must answer
"what specific evidence could materially improve THIS existing lesson," not "what else exists on
this topic."

The pedagogical audit (see `M17.6-DAYS-09-12-AUDIT.md`) found all four days — Programming Logic
(Day 9), Functions/Data Structures/JSON (Day 10), Git and GitHub (Day 11), and What AI Actually Is
(Day 12) — to be accurate, clearly explained, appropriately scoped, and directly assessed against
every stated objective, with no dated claim, factual gap, or missing-context signal that would
justify opening an external source. The subject matter across this batch (Python core-language
syntax, the JSON standard, Git/GitHub's core workflow, and the standard AI⊃ML⊃DL taxonomy) is
foundational and stable rather than time-sensitive — unlike, for example, Day 1's NPU gap (M17.1,
§46/§47), which was a genuine dated omission in a hardware-trends topic that does shift year to
year.

Two candidate research angles were considered during the audit and resolved by direct inspection
of the existing lesson text, without needing to open anything external:

1. **Day 10** — whether the lesson's "filter by content-block type, not position" API-navigation
   guidance is still accurate practice. Resolved as **FACT, already correct**: this matches how
   ordered, typed content-block APIs are documented to behave (this project's own
   `shared/tool-use-concepts.md` reference material, already in this session's context, describes
   exactly this pattern for the Claude Messages API — cross-referenced for confirmation, not
   opened as a new external fetch, since it is part of this environment's existing reference
   material, not a resource being verified for the curriculum).
2. **Day 11** — whether the lesson's silence on `git push` authentication mechanics (GitHub moved
   away from password auth over HTTPS some years ago) constitutes a gap. Resolved as
   **INFERENCE, no gap**: the lesson never asserts or implies a specific authentication mechanism
   — it stays at the conceptual workflow level (stage/commit/push/branch/PR) — so there is no
   claim to update.

If a future batch or a targeted revisit finds a genuine gap in any of these four days, that
would be the trigger to open sources then, not a reason to have opened them speculatively now.
