# CURRICULUM V2 — UPDATED DECISION RULES

These rules govern Level-2 consolidation and later implementation.

## RULE 1 — DO NOT REWRITE AUTOMATICALLY

A researched topic does not justify adding a lesson.

## RULE 2 — PRESERVE STRONG CONTENT

If existing content already satisfies the V2 competency and evidence requirements:

**KEEP**

Do not rewrite merely to demonstrate change.

## RULE 3 — CONSOLIDATE BY LEARNING OBJECTIVE

The goal is NOT to maximize lesson count.

Multiple closely related concepts may belong in one micro-learning when they support one coherent learning objective.

Do not split concepts unnaturally.

Do not merge concepts when doing so damages comprehension or creates excessive cognitive load.

## RULE 4 — MICRO-LEARNING TARGET

Target:
**~5 minutes**

Not a rigid timer.

A valid micro-learning has:
- one coherent objective
- focused explanation
- one clear takeaway
- one recall question

3–6 minutes can be valid.
Longer is acceptable when necessary for coherence.
Very long content should be reviewed for possible decomposition.

## RULE 5 — MICRO-QUIZ

Every micro-learning gets exactly:
**1 recall/retrieval question**

The question:
- tests explicitly taught content only
- focuses on the key takeaway
- is non-gated
- should not be a trick question

Feedback:
- correct → short WHY
- incorrect → correct answer + short WHY

## RULE 6 — MODULE POST-TEST

Post-test occurs at the end of the module.

- pass threshold = 70%
- module completion requires passing
- use a question pool and/or meaningful randomization
- do not rely on identical static tests across attempts

## RULE 7 — DIGITAL LEARNING HAS PRIORITY

When scope conflicts occur:
prioritize core Digital Learning competency over additional AI breadth.

## RULE 8 — AI DOES NOT REPLACE PROFESSIONAL KNOWLEDGE

AI can draft:
- objectives
- questions
- scripts
- storyboards

That does not remove the need to learn how to design, evaluate, verify, and improve them.

## RULE 9 — AVOID ENGINEERING CREEP

Do not turn:
- AI Fundamentals → AI engineering
- E-Learning Technology → LMS administration
- SCORM → SCORM engineering

## RULE 10 — PRACTICAL WHERE PROFESSIONALLY VALUABLE

Prioritize practical work for:
- needs analysis
- SME interviewing/synthesis
- objectives/alignment
- assessment
- storyboard/script
- wireframe/prototype
- Moodle course workflow
- H5P
- accessibility QA
- prompting
- AI critique/verification

## RULE 11 — CONCEPTUAL WHERE SPECIALIST

Keep primarily conceptual:
- xAPI
- LRS
- LTI
- RAG
- embeddings

## RULE 12 — COMPLETION IS NOT LEARNING

Do not equate:
- completion
- SCORM status
- dashboard progress
- activity counts

with learning, behavior, or performance.

## RULE 13 — HUMAN VERIFICATION IS A SKILL

AI-related learning must teach:
DEFINE → PROMPT → GENERATE → CRITIQUE → VERIFY → DECIDE

## RULE 14 — TOOL UI IS NOT THE COMPETENCY

Avoid dependency on specific ChatGPT/Claude/Gemini buttons or rapidly changing interfaces.

## RULE 15 — ACCESSIBILITY IS PART OF DESIGN

Accessibility must appear throughout design and QA, not only at the end.

## RULE 16 — EVIDENCE BEFORE MAJOR CHANGE

For every major change document:
- current state
- evidence/gap
- recommendation
- learning value
- implementation impact

## RULE 17 — OWNER APPROVAL BEFORE CODE

Level-2 consolidation must produce an architecture recommendation.

Do not implement application curriculum changes until owner approval.
