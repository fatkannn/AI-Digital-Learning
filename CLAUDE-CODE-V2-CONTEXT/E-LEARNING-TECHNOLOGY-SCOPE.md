# E-LEARNING TECHNOLOGY — V2 UPDATED SCOPE

## Goal

Make the learner capable of understanding and performing essential Digital Learning technology workflows without becoming an LMS administrator or developer.

Technology must serve learning.

---

## LMS — MUST + PRACTICAL AWARENESS

Understand:
- course structure
- resources
- activities
- access
- completion
- grades
- tracking
- reporting

The learner should understand how LMS features affect the learning experience and learning evidence.

---

## MOODLE — MUST + PRACTICAL

Minimum:
- understand/create basic course structure
- add resources
- add activities
- configure basic completion
- understand quiz/activity workflow
- understand learner progress
- basic course QA
- basic reporting

Role scope:
**Course Creator / Teacher perspective**

OUT OF SCOPE:
- server administration
- infrastructure administration
- plugin development
- plugin installation
- advanced role provisioning

---

## H5P — MUST + PRACTICAL

Focus on learning value.

Potential activities:
- Interactive Video
- Branching Scenario
- Course Presentation
- quizzes/checks
- other appropriate H5P activity types

Teach:

learning objective
→ interaction choice
→ learner action
→ feedback
→ QA

Do not teach a content type merely because it exists.

OUT OF SCOPE:
- CSS/server hosting unless separately justified
- H5P development

---

## SCORM — MUST

Conceptual + workflow exposure:

- package
- LMS integration
- completion
- score
- time
- attempts/status
- interoperability
- publishing behavior
- limitations
- practical awareness of SCORM 1.2 vs 2004

Ideally the learner sees/uses a SCORM package in an LMS workflow.

OUT OF SCOPE:
- manifest coding
- SCORM engineering
- deep implementation differences

---

## xAPI / LRS — SHOULD

Understand:

Actor → Verb → Object

and:
- event-based learning data
- learning experiences beyond the LMS
- LRS role
- relationship to learning analytics

OUT OF SCOPE:
- writing xAPI JSON
- LRS infrastructure configuration

---

## LTI — NICE

Conceptual awareness:
- external tool integration
- interoperability
- relationship to LMS ecosystems

OUT OF SCOPE:
- implementation engineering

---

## LEARNING ANALYTICS — SHOULD

Learner must distinguish:

completion
→ activity/engagement
→ learning
→ behavior/transfer
→ performance/business impact

Analytics must not be treated as proof of learning by itself.

---

## TECHNOLOGY DESIGN PRINCIPLE

Always ask:

> What learning problem does this technology solve?

Do not teach tools as feature catalogs.
